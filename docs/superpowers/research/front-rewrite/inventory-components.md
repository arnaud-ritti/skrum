### 1.4 Dark mode — current mechanism

Stock Laravel React starter-kit mechanism, three cooperating pieces:

1. **Client store** `resources/js/hooks/use-appearance.tsx`: module-level `currentAppearance` (`'light' | 'dark' | 'system'`) exposed with `useSyncExternalStore`. `updateAppearance(mode)` writes `localStorage['appearance']`, writes cookie `appearance=<mode>` (path `/`, max-age 365 days, SameSite=Lax), toggles the `dark` class on `<html>` and sets `document.documentElement.style.colorScheme`. `initializeTheme()` (called from `app.tsx`) seeds `system` if nothing is stored and subscribes to `matchMedia('(prefers-color-scheme: dark)')` changes.
2. **Server** `app/Http/Middleware/HandleAppearance.php` shares `$appearance` (cookie value or `system`) with the Blade view; `bootstrap/app.php` exempts `appearance` and `sidebar_state` from cookie encryption.
3. **Blade** sets `class="dark"` for an explicit dark cookie and runs the inline script for `system`.

Tailwind side: `@custom-variant dark (&:is(.dark *))` and a `.dark { … }` variable block. UI: `components/appearance-tabs.tsx` (light/dark/system toggle) on the settings appearance page. Consumers of the resolved theme beyond CSS: the sonner `Toaster` and the whiteboard (Excalidraw theme) — see sections 2 and 7.

### 1.5 Avatars — current mechanism

- **DiceBear, rendered server-side in PHP** (`dicebear/core` ^10.7 + `dicebear/styles` ^10.6 Composer packages), no JS avatar library and no external HTTP call.
- Route `GET avatars/{seed}.svg` (`avatars.show`, seed constrained to `[a-f0-9]{32}`) → `app/Http/Controllers/AvatarsController.php`: loads `vendor/dicebear/styles/src/{style}.json`, renders `new Avatar($definition, ['seed' => $seed])`, returns SVG with `Cache-Control: public, max-age=31536000, immutable` and a locked-down CSP.
- **Style**: `config('skrum.avatar_style')` = `env('SKRUM_AVATAR_STYLE', 'thumbs')`, validated against `^[a-z0-9-]+$` and file existence, falling back to `thumbs`.
- **Seed**: first 32 hex chars of `hash_hmac('sha256', <identity>, app.key)`. Identity is `User::id` for accounts (`app/Models/User.php::avatarUrl()`), and `user_id ?? id` for participants/players/guests (`app/Concerns/HasGuestIdentity.php::avatarSeed()`; `GamePlayer` defers to its retro participant's seed when it has one). So a person keeps the same avatar as member and as participant, guests get one per participant record, and the seed never exposes the id.
- The front end only ever receives a relative `avatarUrl` string in props / presence payloads and renders it through `components/ui/avatar.tsx` (`AvatarImage` + initials `AvatarFallback`). Used in: poker `players-grid`, `watching-row`; retro `presence-strip`, `health-check-panel`, `survey-card`, `results/participants-section`, `results/games-played-podium`, `results/games-played-round`; games `players-list`, `room-scores`, `team-leaderboard`; action-items `action-item-card`; integrations `people-panel`.
- **Gap / leftover**: `components/user-info.tsx` and `components/app-header.tsx` read `auth.user.avatar` (starter-kit field, typed `avatar?: string` in `types/auth.ts`). `HandleInertiaRequests` shares `'user' => $request->user()` and the `User` model has no `avatar` column, accessor or `$appends` (no `avatar` in any migration), so **the signed-in user's own avatar in the sidebar/header always falls back to initials** (`use-initials.tsx`) — the DiceBear avatar is not used there.

### 1.6 GIFs — current mechanism

- **Server-side proxy over Giphy or Tenor**; the browser never talks to the provider and no API key reaches the client.

### resources/js/components/realtime

Both components are board-agnostic and receive an already-joined Echo presence channel (`presence: WhisperChannel`, i.e. anything with `whisper` / `listen` / `stopListening`). The caller chooses the channel; neither file names one. Both build their transport once in `useState`, so callers must remount them (key by channel, see `channelKey` in `lib/realtime/whisper-transport.ts`) when Echo swaps the channel object.

**Transport (shared, `lib/realtime/whisper-transport.ts`):** `whisperTransport(channel, event, accept)` returns `{ send(message), onMessage(handler) }`. `send` → `channel.whisper(event, message)` (errors swallowed if the channel was left). `onMessage` → `channel.listen('.client-<event>', …)`; the sender id is taken from the server-stamped `metadata.user_id` (Reverb `accept_client_events_from = members`), never from the payload; messages without a sender id or rejected by `accept(senderId, raw)` are dropped. So these are pure client-to-client whispers over the Reverb WebSocket: nothing is persisted and no HTTP route is involved.

## Game types and their full interaction surface

`GameKind = 'draw' | 'gif' | 'hangman' | 'decoded'` (`lib/games/types.ts`). `game-board.tsx` switches on `round.game`; unknown kinds render "This game is not available.". `DrawBoard` and `DecodedBoard` are keyed by `round.id` (tool state and previews reset each round); `HangmanBoard` and `SprintGifBoard` are not keyed.

Common to every game:
- **Start**: host only (`StartRoundControls`); non-hosts see "Waiting for the host to start.". Button label "Start" (first round, heading "Ready to play?") or "Next round" (on the end card). `POST games.rounds.store` (`GameRoundsController.store(room.id)`), body `{leader_player_id}` only for leader games (`draw`, `decoded`). Leader games need 2+ online players ("Waiting for another player") and show a `LeaderPicker` select ("Who draws?" / "Who gives the clues?") pre-filled by endless rotation (`nextLeaderId`).
- **Pass / give up**: `PassRoundButton`, visible to host or the round leader, under every board. Label "Give up" for hangman, "Pass" otherwise. `GameRoundPassesController.store({room, round})`.
- **Timer** (room-level, not per game): `RoomTimer` in the header. Host (non-icebreaker) dropdown: 1, 2, 3, 5, 10 min (":count min") and "Stop timer". Everyone sees the badge `m:ss` (tabular-nums) or destructive badge "Time's up" at 0. Ticks every 250 ms, corrected by server-clock offset.
- **Scoring displays**: `RoundPoints` badges "+:points :name" on the end card (only awards > 0); sidebar "Scores" tab (`RoomScores`, ranked list, "No points yet.", "Reset scores" with confirm dialog for managers); `TeamLeaderboard` on the games index page (period toggle "Last 30 days" / "All time", streak badge ":count-week streak" from 2 weeks, ":wins wins · :rounds rounds", points). Leaderboard is updated optimistically client-side on round end (`withAwardedPoints`), order = points, wins, name.
- **End card** (`RoundEndCard`): outcome badge (`Guessed`, `Solved`, `Lost`, `Time's up`, `Passed`, `Revealed`, `Abandoned`), the word, the question, GIF results, ":name found it!", round points, next-round controls. Winner gets a green check in the players list.
- **History**: `HistoryDrawer` (right sheet, "History" button, title "Last rounds", "No rounds played yet."). List rows show `word ?? question ?? '—'` + outcome badge; clicking opens `RoundDetail` (fetch `GameRoundsController.show`), with "Back". Detail per game: hangman = final mask + "Letters tried: :letters"; draw = read-only `DrawingCanvas` replay + word; decoded = `ClueRow` + word; gif = question + `GifRoundResults`. Also "Led by :name".
- **Switching game**: host `GameSwitcher` select in header (`GameSwitchesController.update`), abandons the current round for everyone; non-hosts see a badge with the game label. Unavailable games are hidden unless current.

### Hangman (`hangman`)
- Components: `HangmanBoard` → `HangmanFigure`, `WordMask`, `LetterKeyboard`.
- Input: **on-screen buttons only** — 26 buttons a–z (`LetterKeyboard`, `role="group"` aria-label "Letters", grid 7/9/13 columns). **There is no physical-keyboard listener** (no `keydown` handler anywhere in the slice); letters are reachable by Tab + Enter/Space as ordinary buttons. Picked letters become `ghost`, disabled, `aria-pressed`.
- Everyone guesses together (no leader). `GameLettersController.store({room, round})` body `{letter}`; the whole keyboard is disabled while a pick is pending.
- Display: SVG gallows with 6 body parts shown proportionally to `misses/maxMisses` (default `maxMisses` 6), text ":count of :max misses", word mask, and "Last letters" chips (last 5 picks, newest first, ":name picked :letter", green border/text on a hit).
- No hints, no chat. Ends by solve/lose/give up/timer.

### Draw & Guess (`draw`)
- Components: `DrawBoard` → `LeaderWord` | `WordMask`, `DrawingCanvas`, `DrawingToolbar`, `HintButton`, `GuessChat`.
- Roles: the leader is the drawer (sees "Your word to draw" + the secret word, fetched via `useSecretWord`); others see the mask and ":name is drawing".
- Canvas: logical 1000×750, raster 800×600, CSS `aspect-[4/3] w-full touch-none ... bg-white`, `cursor-crosshair` for the drawer. Pointer events (mouse left button, touch, pen) with pointer capture; a second finger during a stroke is ignored; pointer up/cancel commits. Strokes auto-split at 400 points.
- Tools (`DrawingToolbar`, `role="toolbar"` "Drawing tools"): **Pen**, **Eraser** (draws in `white`), **Fill** (flood fill at click point), **Undo** (last op), **Clear** (two-click confirm: "Clear" → "Click again to clear", destructive variant, reverts after 3000 ms). Undo/Clear disabled when no ops. Choosing a colour while on eraser switches back to pen.
- Colours (6 swatches): black, red, orange, green, blue, purple. Sizes (3): 4, 10, 24 (logical units). Defaults: pen, black, 10. No keyboard shortcuts.
- Realtime: live stroke previews are whispered on the presence channel as `game-stroke` every 40 ms in chunks of at most 100 points; committed ops go over HTTP in a strict serial queue (`GameDrawingOpsController.store` body `{client_op_id, op}`, undo `GameLastDrawingOpsController.destroy`, clear `GameDrawingsController.destroy`) and are broadcast as `game.drawing.op-added` / `.undone` / `.cleared`. Viewers drop a remote preview once its id is in `committedOpIds`, or after 3000 ms of silence.
- Hints: drawer-only `HintButton` "Reveal a letter (:count left)" (`GameRoundHintsController.store`), `left = maxHints - letters visible on mask`.
- Guessing: `GuessChat` (see Decoded).

### Decoded / emoji clue (`decoded`)
- Components: `DecodedBoard` → `LeaderWord`, `ClueEditor`, `HintButton` (leader) | `ClueRow` (others), `WordMask`, `GuessChat`.
- Leader ("Your word to describe"): 5 emoji slots (`ClueSlots = 5`). Next empty slot is a "+" button opening the shared `EmojiPicker` (`@/components/retro/emoji-picker`, fed `snapshot.emojiData`); filled slots are buttons that remove the emoji on click (aria-label "Remove :emoji", X badge on hover/focus). Letter-like emoji (regional indicators, keycaps, enclosed letters) are refused client-side with toast "Use emoji only, without letters or digits.". Edits are optimistic and saved debounced 300 ms (`GameRoundCluesController.update` body `{clue}`), last edit wins. Helper text "Describe the word with up to five emoji, without letters or digits.".
- Others: ":name is giving clues", read-only `ClueRow` (aria-label "Clue: :emoji" / "No clue yet"), mask.
- Guessing (`GuessChat`, shared with Draw): text input max 50 chars, placeholder/aria-label "Your guess", submit with **Enter** or "Guess" button (`GameGuessesController.store` body `{text}`). List is `aria-live="polite"`, auto-scrolls to bottom, keeps last 50, "No guesses yet.". Own near miss shows badge "Very close!" (only to the guesser). Correct guess: toast "You found it!" and round ends. Leader sees "You know the word, so you cannot guess." instead of the form.
- Hints: leader `HintButton`, same as Draw.

### Sprint GIF (`gif`)
- Components: `SprintGifBoard` → `GifQuestionBanner` + (`GifAnswerStage` before reveal | `GifVotingStage` after `round.revealedAt`).
- Question: host can "Shuffle question" (PUT with empty body) or "Edit question" (inline form, max 200 chars, Enter/"Save", "Cancel") via `GameQuestionsController.update`, only until the first answer exists.

- Voting stage: "Vote for your favourite GIF.", live counter ":count of :total voted" (`aria-live="polite"`, total = max(online, voters)); grid of tiles captioned "Your GIF" / "by :name" / "Anonymous GIF" (anonymous retros); heart button "Favourite" ↔ "Your favourite" (`aria-pressed`, click again retracts); cannot vote for own GIF; one vote per player; vote counts hidden until closed; host "Finish round" (`GameClosuresController.store`).

- No leader, no word, no hints, no chat.

## Answers to the extra questions

### Where poker statistics are computed
**Server-provided, entirely.** `app/Actions/Poker/PokerResult.php` (`PokerResult::compute`) builds `{ average, distribution, mode, consensus, nearestCard }` and `app/Actions/Poker/PresentPokerRound.php` puts it on `round.result` (type `PokerResult` in `lib/poker/types.ts`). There is no client-side statistics module.
- **Average**: server; `null` for non-numeric decks or when there are no countable votes. Client only formats it (`formatAverage`, max 1 fraction digit, locale from `usePage().props.locale`).
- **Consensus**: server boolean (`count($countable) === 1`, i.e. one distinct non-special value). Client shows a `Consensus` badge.
- **Vote distribution**: server array `{value, count}[]` in deck order, zero-count cards omitted, special cards (`?`, `☕`) included. Client-side derivations only: bar width `count / max(count) * 70%` (`result-panel.tsx`), expansion into one card per vote (`anonymous-values-row.tsx`), `value × count` list (`round-votes.tsx`).
- **Mode / nearest card**: server. Client-only logic is `suggestedEstimate()` in `facilitator-toolbar.tsx` (nearest card for numeric decks, else the single mode, else none) to preselect the estimate.
- **"Conflict detection"**: there is no vote-spread/outlier detection anywhere in this slice. The only "conflict" is the **tracker estimate conflict** (`task.external.estimateConflict = { sourceEstimate, matchingCard }`), computed server-side (`PokerTaskSync::estimateConflict`, surfaced by `PresentPokerTask`) and resolved via `PokerEstimateConflictsController.store`. Client only renders it (`estimate-conflict.tsx`).
- Client-computed counters: `gameReducer.withTasks` recomputes `game.tasksCount` and `game.estimatedCount` after task upsert/remove/reorder; `game.totalPoints` is server-only and is not recomputed locally (stale until next refetch).

### Timers
- Facilitator-only, only while a round is open and unrevealed and the game is not ended (`RoundTimerControl`). Dropdown presets `30 s`, `1 min`, `2 min`, `3 min` (`PresetSeconds = [30, 60, 120, 180]`), `Custom minutes…` (dialog, integer 1–60, default `5`), and `Stop timer` (disabled when no timer). Calls `PokerTimersController.update({game, round})` with `{ seconds }` (`null` stops); response `{ timerEndsAt }` is applied locally as `timer.set`.
- Everyone sees `RoundCountdown` → shared `@/components/retro/timer-display` (`TimerDisplay endsAt offset`), keyed by `timerEndsAt`, hidden once revealed/ended/no timer.
- Clock skew: `serverOffset` from `useServerOffset(snapshot.serverTime)` (`@/hooks/use-countdown`).
- Broadcast: `.timer.changed` `{ roundId, timerEndsAt }` on `poker.{gameId}`.

### Auto-reveal
- Game setting `autoReveal` ("Reveal automatically when everyone has voted or the timer ends"); header badge `Auto-reveal`.
- The server decides. Voting response carries `revealed: true` → voter's client refetches. `round.revealReason` ∈ `manual | everyone_voted | timer` drives the result-panel sentence.
- `AutoRevealTriggers` (renders nothing) runs on the **facilitator's** client only: 2 000 ms-debounced `PokerAutoRevealsController.store({game, round})` when (a) a presence member leaves (`departures` counter from `Game`) or (b) the local countdown reaches 0. Refetches if response `{ revealed: true }`; errors swallowed.

### Spectator mode
- `SpectatorToggle` in the header for everyone (hidden when game ended): button `Watch only` / `Play`, `aria-pressed`. `PlayerRoleMenu` (facilitator only, not on self): `Make spectator` / `Make player`. Both call `PokerSpectatorsController.update({game, player})` with `{ spectator }`, then refetch.
- Effects: `me.canVote` false → `Hand` replaced by "You're watching — switch to Play to vote"; spectators are not seated in `PlayersGrid` (unless they voted and the round is revealed non-anonymously); online spectators are listed in `WatchingRow`; presence avatars get an eye badge.

### Cursors / reactions
- Cursors: `GameCursors` wraps shared `@/components/realtime/live-cursors` (`LiveCursors`), whisper event `cursor` (listened as `.client-cursor`) on the presence channel. Shown only when `game.cursorsEnabled`, game not ended, and **no round is open** (no current task, or round revealed) — a pointer over the hand would leak a hidden vote. Per-user "Hide my cursor" toggle in the header, persisted via `useLocalPreference(HideMyCursorKey)` = localStorage key `skrum.hideMyCursor` (shared with retro/whiteboard). Scoped to the `<main>` element.
- Reactions: `GameReactions` wraps shared `@/components/realtime/flying-reactions` (`FlyingReactions`), whisper event `reaction` (`.client-reaction`). Shown when `game.reactionsEnabled` and game not ended, in every round state. Toolbar positioned with `className: 'bottom-28'` to clear the sticky hand. `originFor={avatarOrigin}`.
- Both are remounted via `key={gameId:channelKey(presence)}` when Echo swaps the channel object. Sender identity comes from Reverb metadata `user_id`, never the payload.

### Task import
- `TasksPane` shows `Import` when `me.canEditTasks`, game not ended and at least one connected tracker (`connectedTrackers(snapshot.integrations)`; sources `jira`, `linear`, `jira_dc`, `github`).
- `ImportTasksDialog`: source toggle (only if >1), mode toggle `iteration` (Sprint / Milestone / Cycle) vs `query` (JQL / GitHub search / Linear search). Container search debounced 300 ms → `PokerImportContainersController.index({game, source}, {query:{q, page:1}})`; iterations → `PokerImportIterationsController.index({game, source}, {query:{container}})`; preview → `PokerImportPreviewsController.store({game, source})` with `{mode, iteration_id}` or `{mode, query, container?}` (container required for GitHub in query mode); import → `PokerImportsController.store({game, source})` with `{external_ids}`. Preview pre-selects all not-already-imported issues; `Select all`; "Showing the first 100. Narrow the query." when truncated; toast `:imported imported, :skipped skipped.`.
- Refresh: `More task actions` → `Refresh from :source` → `PokerImportRefreshesController.store(game)`; toasts `:count tasks refreshed.` and warning `:count tasks were not found in :source.`.
- Per imported task: `TaskSourceChip` (key + done tick), `TaskSourceDetails` (link, assignee, source estimate, sync badge, status, missing, `Sync again`/`Retry` → `PokerTaskSyncsController.store`), `EstimateConflict`. Imported tasks cannot be edited in skrum (pencil hidden when `task.external !== null`), but can be deleted by the facilitator.

### Decks
- Built-in decks come from the server as `deckOptions: PokerDeckOption[]` (`{value, label, cards}`); default choice is `fibonacci`. `custom` is always rendered last; team saved decks (`SavedPokerDeck {id, name, cards}`) are listed under "Your team's decks".
- Custom deck: comma-separated input (placeholder `1, 2, 3, 5, 8`), checkboxes `Add ?` and `Add ☕` (default on), optional "Save this deck for the team as…" (max 40 chars, only when `allowSaveAs`). Payload keys: `deck`, `custom_cards[]`, `include_unknown`, `include_coffee`, `save_deck_as`, or `{deck:'custom', saved_deck_id}`.
- In-game: deck is locked once `game.hasVotes` ("The deck can't change once votes exist."). Saved decks loaded lazily from `PokerSavedDecksController.index(game)` only for the facilitator while unlocked. `game.isNumeric` (server) switches the result panel between Average/Nearest card and Most played. Special cards `?` and `☕` are excluded from the estimate select.

### Keyboard shortcuts
**There are no global keyboard shortcuts in the poker slice** (no `keydown` listeners, no number-key voting). What exists:
- Title editor (`game-header.tsx`): `Enter` commits (blur), `Escape` cancels and restores.
- Task reordering via dnd-kit `KeyboardSensor` + `sortableKeyboardCoordinates`: `Space`/`Enter` pick up, arrow keys move, `Space`/`Enter` drop, `Escape` cancel — with translated screen-reader instructions and live announcements.
- Everything else is native button/radix behaviour (cards in the hand are real `<button aria-pressed>`).

### Slice notes

- **No file in this slice is unused and none is a starter-kit leftover.** Every poker component has at least one importer; `lib/utils.ts` is starter-kit in origin but fully used.
- **Statistics are server-side.** The rewrite must not reimplement average/consensus/mode/nearest card; it only needs `PokerResult` rendering. There is no vote-outlier/"conflict" highlighting today — "conflict" only means tracker estimate conflict.
- **Pure logic to keep as-is:** `lib/poker/game-reducer.ts`, `lib/poker/types.ts`, `lib/poker/format.ts`, `lib/realtime/*`, `lib/reverb-config.ts`, `lib/utils.ts`; plus logic currently living inside components that should move to `lib/poker`: `deckChoiceFromGame` / `deckPayload` / `splitCustomCards` / `emptyDeckChoice` (`deck-fields.tsx`), `cardFace` (`players-grid.tsx`), `showsPokerCursors` (`game-cursors.tsx`), `suggestedEstimate` (`facilitator-toolbar.tsx`), `importTerms` (`import-tasks-dialog.tsx`).
- **Privacy rules that are easy to lose:** cursors disabled while a round is open; anonymous rounds keep every seat face-down after reveal and show values only in deck order without names (table and history); spectators' seats hidden; whisper sender identity taken from server metadata.
- **Duplicated patterns worth one primitive each:** the `busy` + `run(retroRequest(...))` + `refetch()` mutation wrapper (repeated in ~12 components); confirm dialogs (end game, delete game, delete task); clipboard copy + `Link copied` toast (header and guest-link dialog); result summary line (result panel, round history, estimates page); checkbox-with-label setting row; tracker status badges; `MarkdownClasses` prose styling.
- **Cross-feature dependencies on `retro/`** that the rewrite should promote to shared modules: `lib/retro/api` (`retroRequest`, `RetroRequestError`), `lib/retro/types` (`PresenceMember`), `hooks/use-retro-channel` (`useSafeConnectionStatus`), `components/retro/{connection-banner, session-expired-banner, presence-strip, timer-display, live-cursor-layer}` (the last only for `HideMyCursorKey = 'skrum.hideMyCursor'`).
- **A11y present and to preserve:** `inert` on the page under the session-expired banner; `role="toolbar"` on facilitator tools; `role="group"` + per-card `aria-label`/`aria-pressed` in the hand; `role="img"` + descriptive labels on seat cards; `aria-current` on the current task; dnd-kit keyboard sensor with translated announcements and instructions; `aria-pressed` on toggles (tasks pane, spectator, hide cursor); `role="alert"` on import errors; sr-only sheet title and external-link text; `aria-labelledby` sections; decorative bars `aria-hidden`.
- **A11y gaps to fix rather than copy:** deck `role="radio"` buttons without roving focus; `role="tab"` buttons without `tabpanel`; many dialogs opt out of descriptions with `aria-describedby={undefined}`; no `aria-live` announcement for reveal, timer end or vote count changes (the only live regions are dnd-kit's and whatever the shared banners/timer provide — not read in this slice).

## Where the logic lives (asked explicitly)

| Concern | Where | Detail |

| **Timer math** | Hook `hooks/use-countdown.ts` (outside slice, read for reference) + `timer-display.tsx` | Server sends absolute `timerEndsAt` + `serverTime`. `useServerOffset(serverTime) = serverTime − Date.now()`; `useCountdown(endsAt, offset)` ticks every 250 ms, returns `max(0, ceil((endsAt − (now+offset))/1000))`; `formatSeconds` → `m:ss`. | **Card grouping** | Server decides; **board.tsx `handleDragEnd`** chooses the call; reducer merges. | Grouping phase + drop on another card → `CardGroupsController.update({retro, card})` with `{parent_card_id}`; response `cards[]` → `cards.upsert`. ## Whiteboard: how it works (cross-file summary)

**Loading Excalidraw**
- Package `@excalidraw/excalidraw` pinned at `0.18.1` (package.json). Many workarounds are tied to that exact version (see flags).
- Lazy: `pages/whiteboards/show.tsx` (outside the slice, read for context) does `lazy(() => import('@/components/whiteboard/board'))` inside `<Suspense fallback={<Skeleton className="h-dvh w-full" />}>` and a class `ChunkBoundary` error boundary with a "The canvas could not be loaded." + Retry screen (retry re-creates the lazy component and re-keys the boundary).
- The library is only ever imported through `lib/whiteboard/excalidraw.ts`, which is the single re-export point and also does the CSS import: `import '@excalidraw/excalidraw/index.css'`. So the CSS ships in the canvas chunk and loads after `app.css` (this is why app.css overrides use `!important`).
- SSR guard: there is no explicit `typeof window` guard around the canvas; the protection is the lazy chunk plus `useSyncExternalStore(..., () => false)` for the theme and `typeof document === 'undefined'` in `use-whiteboard-toolbar-slot`. There is no `resources/js/ssr.tsx`; `config/inertia.php` has an `ssr` block whose enabled state I did not verify.

**Theme**
- `lib/whiteboard/appearance.ts`: `subscribeToTheme` is a `MutationObserver` on `document.documentElement` filtered on the `class` attribute; `isDark()` reads `classList.contains('dark')`. `board.tsx` feeds both to `useSyncExternalStore` and passes `theme={dark ? 'dark' : 'light'}` to `<Excalidraw>`. It does not use `useAppearance`; it follows the `dark` class that `use-appearance` toggles. The library's own theme toggle is disabled (`canvasActions.toggleTheme: false`).
- Excalidraw dark mode is a CSS filter `invert(93%) hue-rotate(180deg)`; `CanvasDarkFilterClass = 'dark:[filter:invert(93%)_hue-rotate(180deg)]'` reproduces it on the sticky colour swatches so they match what the canvas will show.
- Locale: `CanvasLocales` maps `en→en, fr→fr-FR, de→de-DE, es→es-ES`, from `usePage().props.locale`, fallback `'en'`.

**Scene sync protocol** (`lib/whiteboard/scene-sync.ts`, framework-free)
- Element identity/version: `stamp = "${version}:${versionNonce}"`. `known` = what the server holds per element, `pending` = unsent, `seen` = last canvas state (stamp + height), `files` = file ids already up/downloaded.
- Outbound: `handleChange(elements, editingTextId)` from Excalidraw `onChange` queues every element whose stamp differs from `known` (skips never-sent deleted elements and images without a `fileId` yet); flush debounced `FlushDelayMs = 300`, batches of `MaxBatch = 200`, `PUT`/update via `WhiteboardElementsController.update(boardId)` with `{ elements }`. Images are uploaded first (`WhiteboardFilesController.store`, multipart, `file_id` + `file`, `X-XSRF-TOKEN` from the `XSRF-TOKEN` cookie). Failure → requeue, retry after `RetryDelayMs = 2000`, `onOffline(true)`.
- Write response `{ seq, fromSeq, rejected[{ id, reason, element }] }`; reasons `invalid | stale | locked | file | full`. A rejection with `element` force-replaces the local copy, with only `id` soft-deletes it locally; every reason except `stale` raises a toast (ids deduplicated by reason).
- Inbound: Echo event `elements.changed` payload `{ seq, fromSeq, elements? }`. Applied directly only when `fromSeq === seq` and elements are inline; otherwise `resync()` = `GET WhiteboardElementsController.index(boardId, { query: { since: seq } })` looped until `wantedSeq` is reached or `MaxIdleFetches = 3` empty fetches. Merge uses Excalidraw's `reconcileElements` (local wins when newer) and `CaptureUpdateAction.NEVER` (remote changes stay out of undo history).
- Recovery: HTTP 409 on the delta (older than the purge mark) or a failed merge → full reload from `WhiteboardSnapshotsController.show(boardId)`, retried with exponential backoff `2000 * 2^(n-1)` capped at `MaxRecoveryDelayMs = 30000`; local unsent elements are kept unless discarding.
- Locked board: a 403 whose `errors` contains `locked` → close the text editor, drop `pending`, reload dropping local-only elements, call `onLocked` (toast "This board is locked." + refetch).
- Fatal statuses `401, 403, 404, 419` → `onFatal` → `useWhiteboard.fail` (401/419 = session expired banner + `inert`; 404 = "deleted" screen; else "ended").
- Fallback polling: `board.tsx` calls `resync()` every `PollMs = 5000` while the socket is not connected.
- Text-container height workaround (`keepContainerHeight`): undoes Excalidraw 0.18.1 shrinking a container when its bound text is edited, by nudging the font size by 1 and back. Easy to lose and invisible in the UI.
- `lib/whiteboard/restore.ts`: sorts by fractional index, drops elements with an invalid index, restores via `restoreElements` (all together, then one by one on failure), and puts the server `version`/`versionNonce` back so loading is never mistaken for an edit.

**Realtime channel**: presence channel `whiteboard.{boardId}` (Echo `join`). Server events: `.elements.changed`, `.timer.changed`, `.board.changed`, `.board.deleted`. Whispers (via `whisperTransport`, listened as `.client-{event}`): `cursor` `{x, y}`, `viewport` `{x, y, width, height}`, plus the flying-reactions whisper from `components/realtime/flying-reactions` (outside the slice).

**Follow mode** (`use-whiteboard-follow.ts`): facilitator (`leading`) whispers `viewport` in scene coordinates on scroll change throttled to `SendEveryMs = 100`, and repeats every `RepeatEveryMs = 2000` for late joiners. Followers accept only messages from `facilitatorMemberId`, fit the rectangle centred (zoom clamped 0.1–30), and auto-pause as soon as their own pan/zoom differs from the last applied view; "Resume" re-applies the last received view. Toggle is board setting `follow_enabled` ("Bring everyone to me").

**Cursors** (`use-whiteboard-cursors.ts`): whisper `cursor`, send throttle 40 ms, TTL 3000 ms swept every 1000 ms, max 50 cursors, drawn through Excalidraw's `collaborators` map with a colour hashed from the member id (`hsl(h 70% 45%)` / `hsl(h 70% 30%)`). Board switch `cursors_enabled`, per-person "Hide my cursor" in localStorage `skrum.hideMyCursor`.

**Sticky tool**: not an Excalidraw tool. A 200×200 rectangle with `customData: { skrum: { kind: 'sticky' } }` (the server recognises the marker), `strokeColor: 'transparent'`, `roughness: 0`, inserted at viewport centre and selected, `CaptureUpdateAction.IMMEDIATELY` (undoable). Six hex colours. The trigger is portalled into Excalidraw's shapes toolbar just before the eraser by DOM injection (`use-whiteboard-toolbar-slot`, MutationObserver, selectors in `ToolbarDom`); when the toolbar is absent it falls back to a button in the top bar; hidden in view-only mode.

**Templates**: in this slice only "Save as template" (`save-template-dialog.tsx` → `WhiteboardTemplatesController.store(boardId)` with `name` ≤ 80, `description` ≤ 300 or null). Picking/previewing/managing templates is in `components/teams/new-whiteboard-dialog.tsx`, `whiteboard-template-preview.tsx`, `whiteboard-templates-dialog.tsx` (another slice).

**Export**: Excalidraw's "save to disk" is disabled (`HiddenSaveToDiskAction`, `export.saveFileToDisk: false`, `loadScene: false`, `saveToActiveFile: false`). Custom UI in the export dialog (`SceneExport`) downloads `serializeAsJSON(..., 'local')` with `source` replaced by `window.location.origin`, as `{title}.whiteboard.json` (illegal filename characters stripped, fallback `whiteboard`). Image export stays via the library's `MainMenu.DefaultItems.SaveAsImage`. Custom main menu: Export, SaveAsImage, SearchMenu, Help, ClearCanvas, separator, ChangeCanvasBackground (the default links to the library's sites are removed). `aiEnabled={false}`.

**app.css rules that belong to the whiteboard** (`resources/css/app.css` ~l.140–213): hide library sidebar trigger, help-dialog header, library browse button and everything after the laser tool in extra tools; reposition `.scroll-back-to-content` and `.whiteboard-reactions` relative to the canvas's bottom controls (mobile layout aware, safe-area inset); hide the lock/unlock context-menu entries when `.whiteboard-canvas[data-facilitator='false']`. ### Slice notes

- **Keep untouched:** everything under `lib/whiteboard/` and the hooks `use-whiteboard*`. They hold the sync protocol and a set of workarounds pinned to Excalidraw 0.18.1 (toolbar DOM selectors, `closeTextEditor` synthetic Escape, the hidden `saveFileToDisk` action key, the dark filter value, the container-height fix). A visual rewrite should only restyle the shell around the canvas (top bar, status bar, menus, dialogs, gone screen).
- **CSS contracts outside React:** `resources/css/app.css` targets `.whiteboard-canvas`, `.whiteboard-reactions`, `[data-facilitator='false']` and library classes with `!important`. A new design system stylesheet must carry these rules over, and the reactions bar geometry in the comments (46 px tall, 16 px from the bottom) must be re-measured if the bar is redesigned.
- **Theme contract:** `dark` class on `<html>`, localStorage key `appearance`, unencrypted cookie `appearance`, inline script in `app.blade.php`. The canvas observes the class. Changing the mechanism (for example to a `data-theme` attribute) needs matching changes in `lib/whiteboard/appearance.ts`, the Blade view and `CanvasDarkFilterClass` (a Tailwind `dark:` variant).
- **Duplicated patterns:** (1) "await request, toast the error" exists four times in the whiteboard alone (`useWhiteboardRequest`, `attempt` in board-menu, `duplicate` in board-menu, save-template-dialog) plus `ctx.run` in the retro board; (2) presence-channel hooks per feature; (3) hand-over dialogs per feature (whiteboard, retro, poker); (4) clipboard copy done both through `useClipboard` and directly; (5) raw `<img className="rounded-full bg-muted">` avatars in participants, podium and round rows instead of one Avatar primitive; (6) bordered list rows `rounded-md border p-2 text-sm` repeated across results sections.
- **Primitives that should exist:** a Section (ResultsSection and SummarySection differ), a Stat (`dt`/`dd`, local to health-section), a segmented Tabs control with the arrow-key behaviour of `completed-tabs`, a radio group (email dialog uses native radios), a progress/bar row (ROTI), a confirm dialog (delete board is hand-built), and chart primitives if more charts come.
- **Charts:** both health charts are hand-rolled SVG with theme tokens, no library, no hard-coded colours. They have `role="img"`, title/desc, and the trend dots are links with `<title>` tooltips. No keyboard-visible tooltip and no data table alternative besides the statement list in `health-section`.
- **Hard-coded colours in the slice:** only `text-amber-700 dark:text-amber-400` (recap-share-dialog), the six sticky hex colours and the hashed cursor HSL (both intentional data), and `text-[11px]` in suggestions-list.
- **A11y to preserve:** `StatusBar` `role="status"`; `inert` on the board when the session expired; facilitator bar `role="toolbar"` with `aria-pressed` toggles; `aria-label` on every icon-only button (Board menu, Timer, lock, follow, back, sticky swatches); summary pending state `aria-busy` + `role="status"`; `completed-tabs` roving tabindex and ArrowLeft/ArrowRight; `fieldset`/sr-only `legend` in the email dialog; `aria-describedby={undefined}` on dialogs without a description; `motion-safe:` on every animation; `autoFocus` on rename and template name inputs.
