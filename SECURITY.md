# Security policy

## Supported versions

Security fixes land on `main` and ship in the next release. Only the latest release is supported; fixes are not backported to older ones.

## Reporting a vulnerability

Do not open a public issue for a security problem.

Report it privately through GitHub: [open a private security advisory](https://github.com/arnaud-ritti/skrum/security/advisories/new). Only the maintainer can read what you send there.

Please include:

- the Skrum version or image tag (shown in the admin footer, for example `0.0.1`);
- how the instance is deployed (Docker compose, Coolify, from source) and which database engine it uses;
- the steps to reproduce, and what an attacker gains.

## What to expect

Skrum is maintained by one person, so there is no guaranteed response time. Your report is acknowledged before anything is made public, and you are credited in the advisory unless you ask not to be.
